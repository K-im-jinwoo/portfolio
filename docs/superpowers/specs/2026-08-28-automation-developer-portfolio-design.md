# 업무 자동화 개발자 포트폴리오 설계

## 1. 목표

김진우의 취업·이직용 포트폴리오를 제작한다. 채용 담당자가 첫 화면에서 업무 자동화 개발자라는 정체성과 핵심 성과를 빠르게 파악하고, 관심 있는 프로젝트의 문제 해결 과정을 상세 페이지에서 검토할 수 있어야 한다.

초기 버전은 실제 이력서에 포함된 프로젝트와 경력을 사용한다. 확인되지 않은 성과 수치는 만들지 않는다.

## 2. 대상 사용자와 핵심 흐름

주요 사용자는 업무 자동화, 사내 시스템, AI 워크플로 관련 개발자를 채용하는 담당자와 실무 면접관이다.

핵심 흐름은 다음과 같다.

1. 홈에서 이름, 직무, 소개, 프로필 이미지와 대표 프로젝트를 확인한다.
2. 프로젝트 목록에서 관심 있는 사례를 선택한다.
3. 상세 페이지에서 문제, 역할, 해결 방식, 기술, 처리 흐름과 검증된 결과를 읽는다.
4. 소개 페이지에서 경력, 학력, 기술 범위와 업무 방식을 확인한다.
5. 공통 하단의 이메일을 통해 연락한다.

## 4. 프로젝트 콘텐츠

### 4.1 Excel 데이터 변환 자동화 프로그램

- 맥락: HIAIR KOREA MES / WinForms 업무
- 기간: 2026.02~현재의 업무 프로젝트 범위
- 문제: 반복되는 Excel 데이터 변환에서 헤더와 규칙이 달라 수작업 설정이 반복됨
- 해결: 사용자가 헤더와 변환 규칙을 설정하고 저장·재사용할 수 있는 PySide6 프로그램 개발
- 기술: Python, PySide6, Excel
- 결과 표현: 반복 변환 절차를 재사용 가능한 도구로 표준화. 정량 수치는 확보 전까지 표시하지 않음

### 4.2 LLM 기반 개인 지식 관리 시스템

- 기간: 2026.07~현재
- 문제: Markdown WIKI가 늘면서 모바일 기록과 검색이 분리되고 기존 질의 응답에 약 80초~2분이 필요함
- 해결: Telegram 입력, n8n 라우팅, WIKI 질의 API, 키워드·가중치 검색, OpenAI Agents SDK Tool Calling을 연결
- 기술: Telegram, n8n, OpenAI Agents SDK, Python, Markdown
- 결과: 초기 응답 10.3초, 재실행 1.02초. 조회 문서와 출처를 포함한 답변 제공

### 4.3 학사 전과 업무 프로세스 시스템

- 기간: 2024.07~2026.02
- 문제: 신청, 접수, 심사, 확정 단계와 상태별 수정 권한을 하나의 업무 화면에서 안전하게 처리해야 함
- 해결: 7개 탭으로 업무를 구성하고 신청·접수·반려·확정 상태별 권한과 처리 기능을 제어
- 기술: C#, ASP.NET WebForms, DevExpress, MSSQL, Stored Procedure
- 결과 표현: 단계별 업무와 권한 제어를 시스템화. 확인되지 않은 처리 시간 절감 수치는 표시하지 않음

### 4.4 고해상도 이미지 Excel Export 성능 개선

- 맥락: HIAIR KOREA MES / WinForms 업무
- 기간: 2026.02~현재의 업무 프로젝트 범위
- 문제: 4,500px 이상, 약 3.6MB의 고해상도 이미지가 다수 포함된 Excel Export에서 메모리 부족과 처리 지연 발생
- 해결: 이미지를 400px로 사전 리사이징하고 Stream 기반으로 로딩
- 기술: C#, .NET, WinForms, Excel Export, Stream
- 결과 표현: 파일 용량과 생성 시간 감소. 실제 감소율은 확인 전까지 표시하지 않음

### 4.5 LG전자 소비자 VoC 라벨링 및 시각화 시스템

- 기간: 2023.02~2024.04
- 문제: 대규모 리뷰 데이터의 라벨링, 시각화, 탭 전환 시 렌더링 상태 관리와 사내 이관이 필요함
- 해결: 약 20만 건 중 3~4만 건을 직접 라벨링하고 워드클라우드·도넛·바 차트를 구현. D3.js SVG 중복 생성과 이벤트 구조 개선. DB 이관과 사내 서버 배포 수행
- 기술: Django, JavaScript, D3.js, SQL
- 결과 표현: 데이터 규모와 담당 범위만 명시하며 확인되지 않은 성능 수치는 표시하지 않음

## 5. 시각 디자인

### 색상

지정된 다섯 색상만 사용한다.

- `#FAFAF8`: 기본 배경
- `#DADADA`: 구분선과 비활성 경계
- `#B0B3B8`: 장식적 요소와 비필수 상태 표시
- `#43464B`: 보조 본문과 필수 메타데이터
- `#0F1012`: 제목, 핵심 본문, 주요 링크

`#B0B3B8`는 `#FAFAF8` 위의 작은 필수 텍스트에 사용하지 않는다. 대비가 필요한 날짜, 역할, 기술과 링크는 `#43464B` 이상을 사용한다.

### 타이포그래피와 레이아웃

- 기본 서체는 Google Fonts에서 제공하는 `Noto Sans KR`을 사용한다.
- 외부 폰트를 불러오지 못해도 읽을 수 있도록 `Noto Sans KR`, `Noto Sans`, system-ui, sans-serif 순서의 폴백 스택을 지정한다.
- 초기 렌더링을 막지 않도록 프레임워크의 폰트 최적화 기능을 사용하고 `font-display: swap`에 해당하는 동작을 보장한다.
- 제목은 큰 크기와 촘촘한 자간으로 구성하되 화면마다 하나의 주요 제목만 둔다.
- 본문은 충분한 행간과 제한된 줄 길이를 사용한다.
- 카드 남용을 피하고 구분선, 여백, 정렬로 정보 그룹을 나눈다.
- 장식용 그라디언트, 과도한 그림자, 다색 포인트와 반복 애니메이션은 사용하지 않는다.
- 상호작용은 링크 밑줄, 색상 변화 또는 이동 표시로 명확히 구분한다.
- 애니메이션은 짧은 전환만 사용하고 `prefers-reduced-motion`을 존중한다.

### 프로필 이미지

- 사용자가 제공한 480×480 투명 PNG를 원본으로 보존한다.
- 승인된 참조 자산은 `docs/superpowers/specs/assets/jinwoo-profile-reference.png`에 보관한다.
- 홈에서는 오른쪽 비주얼 영역에 약 260px 크기로 배치한다.
- 소개 페이지에서는 약 280px 크기로 재사용한다.
- 배경에는 `#DADADA` 원형 면만 사용하고 이미지 자체는 변형하거나 재생성하지 않는다.
- 대체 텍스트는 `노트북으로 작업하는 김진우 개발자 캐릭터`로 설정한다.

## 6. 반응형 동작

- 데스크톱: 히어로를 소개와 이미지의 2열로 구성한다.
- 태블릿: 너비에 따라 열 간격과 제목 크기를 축소한다.
- 모바일: 히어로를 1열로 전환하고 소개 다음에 이미지를 배치한다.
- 프로젝트 행은 모바일에서 제목과 기술을 유지하고 보조 수치는 다음 줄 또는 상세 페이지로 이동한다.
- 프로젝트 상세의 메타데이터와 처리 흐름은 2열 또는 1열로 재배치한다.
- 최소 320px 너비에서 수평 스크롤 없이 읽을 수 있어야 한다.

## 7. 콘텐츠와 컴포넌트 경계

- `content/projects`: 프로젝트 제목, slug, 기간, 역할, 기술, 문제, 해결, 결과, 단계

- 알 수 없는 프로젝트 주소는 404로 처리한다.
- 프로필 이미지 로딩 실패를 검증할 수 있도록 빌드 대상 자산으로 포함한다.

- GitHub URL과 이력서 파일이 제공되지 않은 상태에서는 빈 링크나 비활성 버튼을 만들지 않는다.

## 9. 검증 기준

- 프로젝트 다섯 개의 slug가 중복되지 않고 필수 필드가 모두 존재하는지 검증한다.
- 홈의 다섯 프로젝트 링크와 소개 페이지 링크가 올바른 경로로 이동하는지 확인한다.
- 각 프로젝트 상세 경로와 404 경로가 빌드 결과에서 정상 응답하는지 확인한다.
- 프로필 이미지와 대체 텍스트가 홈과 소개 페이지에 존재하는지 확인한다.
- 320px, 768px, 데스크톱 너비에서 레이아웃이 겹치거나 잘리지 않는지 확인한다.
- 키보드만으로 모든 링크에 접근할 수 있고 포커스가 보이는지 확인한다.
- 필수 텍스트에 충분한 색상 대비가 있는지 확인한다.
- 프로덕션 빌드를 실행하고 오류 없이 완료되어야 한다.
